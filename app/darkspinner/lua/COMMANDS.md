# In-game command scenario coverage

Source audit: 2026-11-07, after the Fang chat split. This is the scenario coverage contract, not evidence of an executed scenario. No build, scenario or test was run during this audit. Scenario authors must keep partial receipts and fail on unknown mutation outcomes instead of retrying commands blindly.

## Admission and observation

Scope: Dark Spin-added commands only. Original-client social commands below are reference material or fixture setup; missing coverage for those commands does not block this task.

Remote acceptance is required as well as local acceptance. A successful loopback scenario does not establish remote compatibility. Repeat the Dark Spin matrix against a separately hosted owned server, using the client's actual remote login/chat path, an administrator granted by that remote server, and an ordinary remote account for denial checks. Verify replies reach the originating client, actual effects occur on that server, and the local launcher does not execute server commands against a separate local game. Keep administrator requirements identical for local and remote users.

For remote `/ss dump`, verify the snapshot on the remote server. For `/bug` and `/b`, verify the client archive, admitted remote diagnostics, and the two-minute remote capture cooldown with its client-only explanation. For `/noreplay`, verify the remote login session and the next mission it controls; for `/kill` and `/victory`, verify the remote world's enemy deaths and committed mission outcome. Do not count local artifact discovery or a local server reply as evidence for these remote cases.

Current limitation: scenario `launch_mode="remote"` is explicitly reserved and rejected by `debug_operation.go`; these scripts currently launch loopback clients. Remote command behavior remains unverified until actual remote-path observations are collected. Do not label this suite local-and-remote passing or silently substitute a loopback run.

Exercise chat with the owned native client: `client.UI:Press("Enter")`, `client.UI:Type(text)`, verify `processed_character_count == #text`, then `client.UI:Press("Enter")`. The API accepts 1–256 printable ASCII characters. This proves only input processing. Capture both the submitted native/Blaze request and correlated reply, then independently observe the resulting server and native state. A response containing “queued”, “requested”, or “triggering” is admission evidence, not proof the action happened. Screenshots are diagnostic evidence, not automatically checked text or gameplay state.

Run against fresh isolated profiles, never ordinary saves. Use at least two owned accounts for social/co-op paths, a separate Mod server/client with a bound imported Spore creature for emotes, and disposable clients/missions for reset, terminal outcomes and exit. The same command must use the chat input path under test; `World:Spawn`, `Hero:SetResources`, `Mission:Complete`, and party fixtures can prepare a case but cannot substitute for its slash-command action.

Authorization is durable account access, not launch mode or a client/profile flag. Ordinary-user commands are `/help`, `/emote`, `/taunt`, `/bug`, `/b`, `/ping`, `/hint`, `/loc`, `/stat`, `/follow`, `/exit`. Every other server slash command requires an authenticated administrator with a valid access revision and peer. Test ordinary-user denial and unchanged state as well as admin success. Unknown slash commands also pass authorization before their unknown-command response; use an admin to assert that response.

The Fang scanner matches case-insensitively, accepts only end/space/tab after a known name, and scans at most 1024 characters; slash recognition requires start, space, tab or `]` immediately before it. Test mixed case, prefix collision (`/healer` must not invoke `/heal`), ordinary chat containing slash text, and one submission/one effect. The server normalizes the first token with `/`, `!`, or control-prefix 0x1f. Alternate server prefixes are transport compatibility cases; ASCII UI input cannot exercise 0x1f. Native built-ins remain native commands rather than being rewritten as Dark Spin commands.

## Running after build/run authorization

These are four independent scripts, not a single passing umbrella test. After a compatible scenario build is authorized and available, start the canonical `bin/game/darkspinner.exe` from `bin/game` with `--headless --no-browser --lua local/commands.lua --lua-timeout 20m`, substituting each of the other three names for subsequent sessions. Use the exact browser-launcher URL emitted by that process. Do not start another normal server or launcher alongside it. End the previous owned session and verify its processes/port have stopped before the next run or rebuild.

The default three-minute Lua deadline is too short for these multi-client/diagnostic cases; `--lua-timeout 20m` is intentional. A failed run retains live state and diagnostic captures. Never rerun just a timed-out mutating chat input to obtain a green result. Preserve relevant failure evidence before the normal scenario cleanup. Complete coverage must not be reported until the scripts have actually run and the explicit native/Mod/cross-player/remote variants above have observations.
